# Architecture

## Layers

```
src/
  app/                 Next.js routes (App Router)
    layout.tsx         Root: global metadata, Organization and WebSite JSON-LD, SiteBanner
    (auth)/            register, login, forgot-password, reset-password, verify-email pages
      actions.ts       Every auth server action (calls the API, sets the session cookie)
    account/           The signed-in user and a sign-out button
    active-lots/       The lot listing: search, filters, order and a page of 20 lots for signed-in dealers
      actions.ts       Its server actions: option counts, and keeping the dealer's filters
      [source]/[lotNumber]/  One lot: everything the auction publishes, its photos, where to bid
    auth/callback/[provider]/route.ts  Google (GET) and Apple (POST) sign-in return here
    sitemap.ts         Generated from the route registry
    robots.ts          Generated by lib/seo/robots.ts
    llms.txt/route.ts  Generated by lib/seo/llms.ts (static)
  components/          Presentational Server Components (SiteBanner)
    AccountNav.tsx     Banner's menu and account links: asks /auth/session, shows the visitor menu with
                       sign in / free trial, or the member menu with the user
    auth/              Auth forms (React Hook Form), PasswordField, PhoneField, Turnstile, SocialButtons,
                       form-helpers (server errors on fields, remembered email)
    LocalTime.tsx      A time in the reader's own time zone: server text, rewritten before paint
    LotFilters.tsx     The lot list's search box, filter bar, All filters sheet, chips and order
  lib/
    site.ts            Site identity (URL, language, description) and URL resolution
    routes.ts          Registry of every public page
    deal.ts            Deal arithmetic: acquisition cost, profit, margin, max bid
    lots.ts            Auction lots from the API: the Lot shape, one page of 20, one lot,
                       its photos, and the formatters both pages share
    lots-fixture.ts    A complete Lot for tests
    lot-filters.ts     The lot list's filters (FILTERS), URL validation (readQuery), chips, promotion
    lot-words.ts       Auction codes in plain words (SIGNALS, vehicle types, auction names), browser-safe
    lot-signals.ts     A lot's badges and labels, from lot-words and the Copart title table
    api.ts             Server-only client for the API; errors become ApiError
    session.ts         Session and OAuth-state cookies, currentUser(), visitor IP and time zone, safePath
    auth-schemas.ts    Zod schemas shared by the auth forms and server actions
    remembered-email.ts  The last complete address typed in an auth form, per tab (sessionStorage)
    countries.ts       Countries with flag, name and calling code; phone composition
    dial-codes.ts      Generated: region code and calling code for 245 regions
    phone-formats.ts   Generated: example number, allowed lengths and trunk prefix per region
    timezone-countries.ts  Generated: IANA time zone → country, for detecting the visitor's
    seo/               Metadata, JSON-LD, robots, sitemap and llms.txt builders
public/
  images/              Static images
```

Dependencies point downward: `app` → `components` → `lib`. The
modules in `lib` are pure functions with no React, so tests can cover them
directly.

## Lot search and filters

The URL is the lot list's state, with the API's own parameter names (`title=salvage&sort=sale`),
so the server renders every list and a list can be shared. `readQuery` (`lib/lot-filters.ts`)
keeps only the parameters and values `FILTERS` allows, in one order, so equal filters make
equal URLs. The page, for a signed-in dealer:

1. With a search (`q`), asks the API what it names (`/api/lots/interpret`): one lot is a
   redirect to it; a make, model or years are a redirect to those filters (`searched`).
2. With no parameters at all, redirects to the filters kept in the dealer's account
   (`/api/me/lot-preferences`). The filter bar always writes `sort`, so a bare URL only comes
   from elsewhere, such as the banner's link; kept filters that read as nothing do not redirect.
3. Lists the page of lots (`/api/lots`) in the dealer's zone (the `cs_tz` cookie).

`LotFilters` turns every change into a new URL (`router.push`, no scroll), so Back undoes a
filter. It asks for option counts (`/api/lots/counts`, through `lotCountsAction`) only for the
dropdown or sheet that is open, since each filter's counts are a scan of the lots, and drops
an answer that arrives after the filters changed. After each change it stores the filters and
order (not the search's words) through `rememberLotFiltersAction`, unless they equal what the
page read; the API counts how often each parameter is set, and the most used move into the bar.

## Layout

The site is full width. There is no centered page container: sections span
the viewport with side padding, and only running text is capped at a readable
line length. Auth pages center their form in one 28rem column (`.auth-panel`).
The top banner shows the site name as plain text on the left and the account
navigation on the right: "Sign in" and "Register", or the signed-in dealer's
initial, name and "Sign out". The navigation is a client component that asks
`/auth/session` (a route handler returning only the first name and email) after
every navigation, so the pages themselves stay static and signing in or out,
which both redirect, updates it.

## Colours and assets

There is no brand name, design system, logo, favicon, manifest or share image
yet, and no structured data. Page titles stand alone, and the banner links home
with the word "Home". The interface uses
black, grey and white only, through the tokens in `src/app/globals.css`
(`--ink`, `--muted`, `--line`, `--paper`, `--surface`), Work Sans (loaded with
`next/font/google` in the root layout, the system font stack behind it), and
no dark mode. Buttons, links, checkboxes and focus rings are all `--ink`;
errors read as bold text rather than a colour. The lot page's deal-breaker
badges and sale countdown are the one exception: green, amber and red
(`--good`, `--warn`, `--bad`), always with an icon and words as well. Add branding once a name and a
design are settled.

## Route registry

`src/lib/routes.ts` lists every indexable page with its title, description,
sitemap priority, and whether it appears in `llms.txt`.
It is empty until the first page is built. Pages read their metadata from it
through `metadataForRoute(path)`. `routes.test.ts` fails if a static `page.tsx`
under `src/app` is missing from the registry. The builders take an optional
route list, and tests pass them `src/lib/seo/fixtures.ts`.

## SEO module

- **Site URL.** `resolveSiteUrl` uses `NEXT_PUBLIC_SITE_URL`, falling back to
  `http://localhost:3000`. Only a `NEXT_PUBLIC_` variable is used, because
  Next.js inlines those into client bundles too, so server and browser always
  agree on the value. Every absolute URL goes through `absoluteUrl()`.
- **Metadata.** `buildMetadata` sets the title, description, canonical URL,
  Open Graph, Twitter card and robots directives. There is no share image yet,
  so the Twitter card is a plain `summary`.
- **Structured data.** None: every schema.org type worth emitting here needs a
  brand name, and there is none yet. The builders come back with the brand.
- **AI crawlers.** `robots.txt` is a single `User-Agent: *` / `Allow: /` rule,
  which admits every crawler, AI search and assistant bots (GPTBot, ClaudeBot,
  PerplexityBot, Google-Extended and others) included. `/llms.txt` summarizes
  the site and links its key pages.
- **Rendering.** Pages should be prerendered to static HTML, so crawlers that
  don't run JavaScript still see the full content.

## Accounts

Accounts live in the API (`../cars-secrets-api`, see its `docs/architecture.md`). This
site never stores credentials or talks to a database. The API client defaults to
`http://localhost:8001`; `API_URL` overrides it for other environments. Start the local
API with `uv run uvicorn app.main:app_factory --factory --reload --port 8001` from
`../cars-secrets-api`. Server actions in
`src/app/(auth)/actions.ts` post to the API through `src/lib/api.ts`, which adds the
visitor's address with the shared `API_INTERNAL_KEY` so the API rate-limits visitors and
not this server.

Forms use React Hook Form and the Zod schemas in `src/lib/auth-schemas.ts`. Errors show
when a field loses focus (`mode: "onTouched"`) and on submit, before any request. Every
input carries the same limit as its schema, so nothing over-long is typed in the first
place. The server action parses
the same schema again, calls the API and returns field errors, which `showServerErrors`
puts on the matching inputs without clearing the form. The email typed in one auth form
is remembered for the tab once it is a complete address, and prefilled in the others;
sign in then focuses the password. Entering a confirmation code or signing out forgets it.

- **Register**: the form posts names, email, the phone (one control holding the country
  picker and the number, joined into `+<calling code><digits>`; the API normalizes to
  E.164), password and the Turnstile token. Agreeing to the Terms of Use and Privacy
  Policy is what the submit button does ("Agree and register", with a sentence saying so),
  so there is no checkbox to validate and the action sends `accept_terms: true` itself. The country defaults to
  the region of the browser's first language (`countryFromLanguages`), and on mount the
  form replaces it with what the browser itself knows (`countryFromBrowser`: its time
  zone first, its languages second). The country's example number is the placeholder, the
  shape the digits are formatted into as they are typed and the ceiling they stop at
  (`formatNational`), and the lengths the number is checked against
  (`isValidNationalNumber`). The password field
  ticks off `PASSWORD_RULES` live — 8 characters, a letter, a number and a special
  character — from the first focus on the input onwards, and warns about Caps Lock. The
  same list is what the schema validates, and the API applies it too. The form also renders the Google and Apple
  buttons, so the code step that replaces it on success replaces them too; "Use a
  different email" goes back to the form with its values.
- **Confirm**: the API mails a six-digit code (valid 10 minutes). `VerifyEmailForm` asks
  for it in one field (`autocomplete="one-time-code"`, numeric keyboard), keeps only the
  digits of whatever is typed or pasted (`codeDigits`) and submits on the sixth. A right
  code signs the dealer in: `verifyEmailAction` sets the session and redirects to
  `/account`. A wrong one clears the field and says so on it. "Send a new code" appears
  after 60 seconds, the API's own minimum between codes. The step follows registration,
  a sign-in on an unconfirmed address, and `/verify-email`, which asks for the address
  first (prefilled from the tab's remembered one).
- **Sign in**: on success the API returns a token, which becomes the `cs_session`
  cookie (30 days with "remember me", browser session otherwise), and the visitor lands
  on `/account`. When the API answers `captcha_required`, the form shows the Turnstile
  widget. A wrong password clears the password (not the email) and offers a reset link.
  A right password on an unconfirmed address makes the API mail a code, and the form
  turns into the code step, keeping "remember me" for the session it opens.
- **Forgot / reset**: `/forgot-password` asks for the email; the emailed link opens
  `/reset-password?token=…`, which sets the new password. The API then signs out every
  session of that user.
- **Google / Apple**: the buttons call `socialLoginAction`, which gets the provider URL
  and a `state` from the API, stores the state in the `cs_oauth_state` cookie and
  redirects. The provider returns to `/auth/callback/{provider}`; the route handler
  compares the state with the cookie, asks the API to finish the handshake and sets the
  session cookie.

The register page builds the country list on the server from `dial-codes.ts` (generated
from the phonenumbers metadata the API uses), names from `Intl.DisplayNames` and flags
from the regional indicator symbols, and passes it to the form, so no flag images ship
and server and browser agree on the names.
To regenerate `dial-codes.ts`, run the snippet in its header against the API's
environment. `phone-formats.ts` carries the example number shown as the placeholder,
the national lengths the number is validated against and the trunk prefix, from the
same metadata; the snippet in its header regenerates it the same way.

## Lot price prediction

The lot page reads `predicted_final_price` from the existing authenticated lot API response
and renders it as "Likely final bid" in the lot's currency. It is a single model estimate,
not a range; null displays "Not available". The ingest model currently trains on generated
sold prices, so this is an estimate rather than a confirmed sale price. No similar-sales
count is claimed. `DealCalculator` still uses explicitly labeled sample costs and profit.
